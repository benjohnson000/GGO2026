# AGENTS.md

Instructions for AI coding agents working in this repository.

## Project

- A match-3 roguelike deckbuilder for GitHub Game Off 2026 (theme: **Shift**).
- Engine: Unity 6 (`6000.6.8f1`), URP 2D, Input System, TextMesh Pro.
- Game design decisions live in [Docs/DESIGN.md](Docs/DESIGN.md). Read it before working on gameplay.

## Read First

- [Assets/Scripts/SCRIPTING_GUIDELINES.md](Assets/Scripts/SCRIPTING_GUIDELINES.md): coding conventions, namespaces, patterns and the pre-commit checklist. Follow it for all C# work.
- [Docs/DESIGN.md](Docs/DESIGN.md): what the game is and which decisions are settled or still open.
- [Docs/ARCHITECTURE.md](Docs/ARCHITECTURE.md): scenes, boot flow, code layout and how data flows. Per-system docs are in [Docs/Systems/](Docs/Systems/); read the one for the system you are touching.

## Keeping Docs Current

- When you change how a system works (public API, event order, asset fields, scene setup), update its doc in `Docs/Systems/` in the same change.
- When you add a new system, add a doc for it and link it from `README.md` and `Docs/ARCHITECTURE.md`.

## Layout

| Path | Contents |
|---|---|
| `Assets/Scripts/` | Game code (`ggo2026` assembly and namespace) |
| `Assets/Scripts/Utilities/` | Reusable, game-agnostic systems (`benjohnson` namespace) |
| `Assets/Scenes/`, `Prefabs/`, `Art/`, `Materials/`, `Resources/`, `Settings/` | Unity assets |
| `Docs/` | Design documentation |
| `Packages/manifest.json` | Package dependencies |

## Rules

- **Do not edit** `Library/`, `Temp/`, `Logs/`, `obj/`, or `UserSettings/`. They are generated by Unity.
- **Never edit `.meta` files by hand.** When creating, moving or renaming an asset or script, keep its `.meta` file alongside it so GUID references survive.
- Avoid hand-editing scene (`.unity`), prefab and ScriptableObject asset files unless the change is small and well understood. Prefer making the change in the Unity Editor, or ask the user to.
- The user is happy to do work in the Unity Editor. When setting something up in the Editor (wiring references, building prefabs, creating ScriptableObject assets, laying out UI) would give a better result than hard-coding it, choose the Editor approach and give the user clear step-by-step instructions.
- Use existing utilities (`Singleton<T>`, `StateMachine<T>`, `SceneController`, `SFXManager`, `MusicManager`, `SaveLoadSystem`, `InputManager`, transitions) before writing new infrastructure.
- Keep game logic in plain C# classes where practical, separate from MonoBehaviour views, so it stays testable.
- Keep tuning values in ScriptableObjects rather than hard-coding them.
- Keep changes scoped to the task. Do not refactor unrelated code.
- Do not add packages or change project settings without asking.

## Design Decisions

- Do not make gameplay design decisions on your own. If a task depends on something listed under **Open Questions** in `Docs/DESIGN.md`, ask the user.
- When the user settles a design question, update `Docs/DESIGN.md` to match.

## Verifying Changes

- Agents usually cannot run the Unity Editor. Check code carefully for compile errors, and tell the user what needs testing in the Editor or Play mode.
- Do not claim a change works in-game unless it has been verified there.
